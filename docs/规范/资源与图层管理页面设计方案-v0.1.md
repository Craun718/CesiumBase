# 资源与图层管理页面设计方案 v0.1

> 日期：2026-09-05
> 状态：已按方案实现
> 维护人：莫
> 上游规范：[图层数据模型与接口规范-v0.2.md](./图层数据模型与接口规范-v0.2.md)

## 1. 目标

本方案覆盖第 3 阶段资源与图层链路：

- 建设资源目录页面，维护资源分类、服务接入和资源。
- 建设图层管理页面，维护图层方案、分组和图层配置。
- 在地图大屏左侧增加图层树，替换原“态势总览”入口。
- 将原“数据服务”入口改为“数据管理”，跳转资源目录页面。
- 将天地图底图纳入资源与图层模型，移除旧底图切换链路。
- 将 DEM 加载迁移到 `LayerRegistry` 统一入口。
- 支持地图端上传 GeoJSON 与 ZIP Shapefile 临时图层。

本期交付完整管理页面与配置能力；除 DEM、天地图和临时 GeoJSON 外，其余协议的真实加载与测试在下一阶段按协议逐步补齐。

## 2. 页面结构

### 2.1 路由

引入 `vue-router`：

```text
/                    地图大屏
/data                数据管理首页，重定向到 /data/services
/data/services       服务接入
/data/resources      资源目录
/data/layers         图层管理
/data/overview       数据总览
```

要求：

- 地图大屏使用 `KeepAlive` 保留地图实例、相机状态和已加载图层。
- 返回大屏时触发地图 resize。
- `/data/services`、`/data/resources` 与 `/data/layers` 共用同一个数据管理页面壳，仅切换内容区。
- 保留现有 `AppTopBar`，管理页提供“返回大屏”入口。

### 2.2 地图大屏入口调整

| 现状               | 调整后                                        |
| ------------------ | --------------------------------------------- |
| 左侧“态势总览”     | 左侧“图层树”，点击打开图层树面板              |
| 左侧“数据服务”     | 左侧“数据管理”，点击跳转 `/data/resources`    |
| 地图操作中的“底图” | 移除，底图由图层树统一控制                    |
| 地图操作中的“地形” | 改名为“地形夸张”，仅控制当前地形 exaggeration |

`OverviewPanel.vue` 当前仅被 `DashboardWorkspace.vue` 引用，样式全部位于组件内 scoped SCSS。实现图层树后删除该组件；其引用的 `RailPanel.vue` 仍被其他面板使用，必须保留。

`DataServicePanel.vue` 的职责已迁移到数据管理路由，实现后删除该组件。清理时需要同步删除 import、左侧入口类型、模板分支和无用状态。

## 3. 数据管理状态

### 3.1 状态分层

```text
catalog     正式配置：资源分类、服务接入、资源、图层方案
transient   会话状态：当前方案、显隐覆盖、临时图层
```

9 月没有自研后端，正式配置仍从 `src/mock/layers.ts` 初始化。管理页修改只保存在当前页面会话，不写 localStorage。

### 3.2 会话内编辑

资源目录与图层管理支持：

- 新增、编辑、删除、排序、启停。
- 服务接入与资源的一对多维护。
- 图层方案、分组、图层配置和发布状态维护。
- 校验失败时阻止保存，并在表单内提示原因。

按钮语义：

| 按钮               | 行为                                       |
| ------------------ | ------------------------------------------ |
| 保存草稿           | 只更新当前会话中的方案配置                 |
| 发布               | 将方案状态更新为 `published`               |
| 发布并应用         | 生成方案下发包并更新地图端当前方案         |
| 恢复初始数据       | 重新从 `src/mock/layers.ts` 初始化会话配置 |
| 复制完整 layers.ts | 生成可整文件替换的 TypeScript mock 文件    |

“复制完整 layers.ts”只导出正式资源、服务接入、分类和方案，不导出用户上传的临时数据。开发者将复制内容整文件替换本地 `src/mock/layers.ts` 后保存，Vite 会热更新；手动刷新页面后也读取最新 mock。

## 4. 资源目录页面

页面采用三栏结构：

```text
左侧：资源分类树
中间：资源列表 / 服务接入列表
右侧：详情与编辑表单
```

### 4.1 二级视图

| 视图     | 职责                                       |
| -------- | ------------------------------------------ |
| 资源目录 | 管理资源分类、资源、启停、排序、搜索和过滤 |
| 服务接入 | 管理服务端点、协议参数、测试状态和派生资源 |

一个服务接入可以派生多个资源。WMS/WFS 服务先注册端点，后续从 Capabilities 中选择子图层生成资源；单资源协议可退化为“一服务接入一资源”。

### 4.2 协议配置范围

本期 8 类协议表单全部可配置：

- `terrain-quantized-mesh`
- `xyz`
- `wms`
- `wmts`
- `wfs`
- `geojson`
- `3d-tiles`
- `gltf`

本期 DEM 提供真实连通性测试；其他协议表单可保存会话配置，测试入口显示“将在协议加载阶段开放”。下一阶段顺序：

1. 影像：XYZ、WMTS、WMS。
2. 矢量：GeoJSON、WFS。
3. 实景三维：3D Tiles。
4. 手工模型：glTF。

### 4.3 删除与停用

- 资源被图层引用时禁止删除，详情页展示引用列表。
- 资源停用后不允许新增引用。
- 已发布方案中引用已停用资源时，该图层不再加载，地图端用错误提示显示“资源已停用”。

## 5. 图层管理页面

图层管理页负责方案编排，不直接操作地图引擎。

能力包括：

- 方案新建、复制、重命名、删除、发布、停用和设为默认。
- 分组新增、重命名、删除、移动、排序和默认展开配置。
- 从已注册资源添加图层。
- 配置图层名称、描述、默认显隐、分组、`sortOrder` 和 `renderOrder`。
- 按图层类型配置透明度、矢量样式等参数。
- 校验引用关系、样式类型、排序字段和地形默认显隐。

规则：

- `sortOrder` 只控制树和列表排序，数值越小越靠前。
- `renderOrder` 只控制渲染叠放，数值越大越靠近视点。
- 影像底图数量不限制，允许多个同时显示。
- 地形图层可配置多个，但发布方案中只允许一个默认显示。
- 修改草稿不即时影响地图，点击“发布并应用”后才更新地图。

## 6. 天地图迁移

### 6.1 资源建模

默认 mock 增加两个正式资源：

| 资源           | 默认显隐 | 说明                       |
| -------------- | -------- | -------------------------- |
| 天地图影像底图 | 显示     | 内部包含影像瓦片和注记瓦片 |
| 天地图矢量底图 | 隐藏     | 内部包含矢量瓦片和注记瓦片 |

注记不单独出现在资源树和图层树中。每个天地图资源在引擎内部创建基础瓦片和注记瓦片，注记使用固定高层渲染位置，避免被其他影像底图盖住。

新建或复制方案时自动预置天地图影像底图；管理员允许删除，不做硬性校验。

### 6.2 Key 与后续对接

9 月天地图 Key 继续从本地 `.env` 的 `VITE_TIANDITU_KEY` 读取：

- 不写入 mock。
- 不提交远程。
- 页面只显示“使用本地环境变量 Key”。

10 月后端完成后，切换为后端代理或受保护服务下发，避免长期 Token 暴露在浏览器端。此要求需同步到图层数据模型与接口规范的后端安全章节。

### 6.3 旧链路清理

- 移除地图操作中的“底图”入口和 `BasemapPanel` 链路。
- 移除 `imagerySources.ts` 中的底图切换能力。
- 删除自定义底图 URL 的本地持久化状态和入口。
- 开发过程中允许短暂保留启动兜底，但方案加载成功后必须由 `LayerRegistry` 接管；最终提交不保留双链路。
- 实现结果：`createViewer` 使用 `baseLayer: false`，旧 `baseImagery.ts`、`imagerySources.ts`、`BasemapPanel.vue` 和自定义底图 URL 持久化状态已删除。

## 7. 地图页图层树

图层树面板能力：

- 切换已发布且启用的方案。
- 搜索图层。
- 展开和折叠分组。
- 控制图层显隐。
- 每个图层提供“缩放至图层”按钮。
- 不展示“类型 / 正常”等常规状态；加载失败或资源停用时显示 6 秒自动消失的错误提示。
- 失败图层可重试。
- 临时图层可移除。

地图端普通用户不提供正式图层新增、删除、排序和样式编辑能力。

隐藏图层采用按需加载：方案应用时只加载默认可见图层，用户打开隐藏图层时再加载。

## 8. 临时上传

上传入口位于地图页图层树，面向普通用户。

| 格式           | 限制 |
| -------------- | ---- |
| GeoJSON / JSON | 20MB |
| ZIP Shapefile  | 50MB |

引入 `shpjs` 在浏览器端解析 ZIP Shapefile 并转换为 GeoJSON。

上传后：

1. 校验文件类型、大小和 GeoJSON 结构。
2. 计算要素包围盒。
3. 创建 `InlineGeoJsonResourceDefinition`。
4. 创建 `origin: "temporary"` 的图层。
5. 加入图层树“临时图层”分组并立即加载。

临时图层只在当前会话内存在，刷新后消失，不进入正式 mock 导出。

## 9. LayerRegistry 与引擎边界

`LayerRegistry` 放在 `src/features/layers`，业务模块只调用它，不直接操作 Cesium Viewer。

本期真实支持：

- DEM：加载、显隐、定位、错误状态。
- 天地图影像和矢量：资源化加载、内部注记、显隐、定位。
- 临时 GeoJSON 与 SHP 转换结果：加载、样式、显隐、定位、移除。

其他协议先返回明确“暂未支持”的错误，不用假成功状态。

地图共享层需要扩展通用图层能力，由 Cesium 引擎实现：

- 添加、移除、更新影像层。
- 添加、移除、更新 GeoJSON 矢量层。
- 后续扩展 3D Tiles 和 glTF。
- 更新透明度、显隐和渲染顺序。
- 飞行到 extent。
- 场景 resize。

DEM 通过适配器转换为现有 `TerrainSource`，再调用 `mapController.setTerrainSource()`。

## 10. 动态更新规则

- 注册资源后，资源目录数据立即更新；地图图层树只有在该资源被加入已应用方案后才出现。
- 新增图层默认可见时立即加载；默认隐藏时仅显示树节点，用户打开后再加载。
- 已应用方案中的资源、服务接入或图层配置保存后，同步重新下发该方案并更新地图对象和树节点。
- 删除已应用方案中的图层后，同步移除地图对象和树节点。
- 停用或删除当前已应用方案时，清除该方案的正式图层，仅保留用户上传的临时图层。
- 只修改草稿时不影响地图。
- 管理页点击“在地图中查看”后跳转 `/`，并飞行到资源 extent。
- 地图端点击“缩放至图层”时，通过该图层引用的资源 extent 飞行。

## 12. 实现决策

- `/data/services`、`/data/resources` 与 `/data/layers` 共用 `DataManagementPage.vue` 管理壳，通过路由切换视图，不重建地图大屏。
- `useLayerCatalogStore()` 是 9 月唯一会话编辑入口，从 `src/mock/layers.ts` 初始化；管理员配置、用户显隐和临时图层都不写 localStorage。
- `CesiumLayerRegistry` 位于业务层，负责方案应用、懒加载、显隐、重试、临时图层和定位；地图共享层只暴露引擎无关影像 / 矢量 / 地形能力。
- 临时上传由 `LayerTreePanel.vue` 触发、`upload.ts` 解析、`layerTree.ts` 建树；正式图层、未分组图层和临时图层共用同一棵树。
- 其他协议配置表单已完整保留；真实加载和测试按第 4.2 节顺序在下一阶段补齐，当前失败信息明确提示“将在下周接入”。
