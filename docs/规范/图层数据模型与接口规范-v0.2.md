## 1. 结论

本规范把原本容易混在一起的“服务、资源分类、资源、图层、分组方案、用户临时状态”拆成六个对象：

```text
DataSourceConfig     数据服务接入：协议、地址、连接参数
ResourceCategory     资源分类：资源树中的目录节点
ResourceDefinition   资源：管理员注册后的可用数据或内联 GeoJSON
LayerDefinition      图层：某个资源在场景中的显示配置
LayerScheme          图层方案：管理员保存的一组分组和图层
TransientSceneState  用户临时状态：当前方案、显隐、临时图层
```

职责边界：

- 管理员负责注册数据源、测试服务、维护资源、配置图层和保存多个图层方案。
- 地图端用户只切换方案、控制显隐、使用临时图层；用户操作不回写管理员方案。
- 绘制成果和分析结果通过 `LayerRegistry.registerLayer()` 挂载，不直接操作 Cesium Viewer。
- 9 月不做真实登录和权限校验；10 月后端接管鉴权、审计、服务目录和方案入库。

## 2. 术语

| 术语         | 含义                     | 关键点                            |
| ------------ | ------------------------ | --------------------------------- |
| 数据服务接入 | 一个可连接的服务端点     | 按协议建模，如 WMS、WFS、Terrain  |
| 资源分类     | 资源树目录节点           | parentId + sortOrder 表达树和排序 |
| 资源         | 管理员注册后的可用数据   | 引用服务接入，或承载内联 GeoJSON  |
| 图层         | 场景中的显示实例         | 引用资源，包含显隐、样式和双排序  |
| 分组         | 管理端和地图端的树节点   | 只影响展示，不决定渲染叠放        |
| 图层方案     | 一套完整分组与图层配置   | 可保存多套，同一时间只启用一套    |
| 临时图层     | 用户上传或分析产生的图层 | 会话内有效，不保存                |
| 用户显隐状态 | 地图端临时隐藏/显示      | 刷新后恢复管理员默认值            |

## 3. 数据服务接入规范

`DataSourceConfig` 是 tagged union。`protocol` 是判别字段， TypeScript 会根据它收窄到具体服务类型。

这类似 Java 的 `sealed interface` + 多个 `record` 实现，但更适合 JSON 序列化：每个 JSON 对象都有一个确定的 `protocol` 标签。

### 3.1 协议清单

| protocol                 | 用途                      | 必填字段示例                        |
| ------------------------ | ------------------------- | ----------------------------------- |
| `tianditu`               | 天地图过渡协议            | `mapType`、`tokenEnvVariable`       |
| `terrain-quantized-mesh` | DEM 地形                  | `url` 服务根目录                    |
| `xyz`                    | XYZ 模板瓦片影像          | `urlTemplate`                       |
| `wms`                    | GeoServer WMS 影像        | `baseUrl`、`layers`                 |
| `wmts`                   | WMTS 影像                 | `baseUrl`、`layer`、`tileMatrixSet` |
| `wfs`                    | GeoServer WFS 矢量        | `baseUrl`、`typeName`               |
| `geojson`                | 在线 GeoJSON              | `url`                               |
| `3d-tiles`               | 实景三维、白膜、点云、BIM | `url` 指向 `tileset.json`           |
| `gltf`                   | 手工单体模型              | `url` 指向 `.gltf` 或 `.glb`        |

协议名描述服务格式，资源类型和图层类型描述业务用途。`terrain-quantized-mesh` 表示 Cesium Terrain 服务，瓦片格式为 `quantized-mesh-1.0`；名称比 `terrain` 长，是为了避免与业务类型 `terrain` 混淆。管理端界面可显示短名称“DEM 地形”。

`tianditu` 是 9 月前端过渡协议，仅用于把天地图影像和矢量底图纳入统一资源模型。它不是通用 OGC 协议；10 月后端代理完成后，可继续保留该协议并隐藏 Token 细节，或改为标准 `wmts` /受保护代理协议，但必须通过规范版本评审后再调整。

### 3.2 DEM 示例

```ts
const demSource: TerrainQuantizedMeshDataSource = {
  id: "source-dem-guangxi",
  name: "广西 DEM 服务",
  protocol: "terrain-quantized-mesh",
  url: "http://127.0.0.1:9001/gx/",
  params: {
    requestVertexNormals: false,
    requestWaterMask: false,
  },
}
```

规则：

- `url` 填服务根目录，结尾必须有 `/`。
- 不填 `layer.json`，CesiumTerrainProvider 会自动请求。
- `authToken` 只在受保护服务需要 Bearer 认证时填写。
- DEM 没有透明度；显隐通过切换地形 Provider 实现。

### 3.3 天地图过渡协议示例

```ts
const tiandituImagerySource: TiandituDataSource = {
  id: "source-tianditu-imagery",
  name: "天地图影像服务",
  protocol: "tianditu",
  mapType: "imagery",
  tokenEnvVariable: "VITE_TIANDITU_KEY",
  subdomains: ["0", "1", "2", "3", "4", "5", "6", "7"],
  maximumLevel: 18,
}
```

规则：

- `mapType: "imagery"` 生成影像瓦片和注记瓦片；`mapType: "vector"` 生成矢量瓦片和注记瓦片。
- 注记瓦片由引擎内部创建，不单独注册资源和图层；注记使用固定高渲染偏移，避免被其他影像层遮盖。
- 9 月 `tokenEnvVariable` 只允许指向 `VITE_TIANDITU_KEY`，真实 Key 不写入 mock 和 Git。
- 10 月后端代理完成后，普通用户接口不得返回长期 Token；如仍需浏览器直连，只允许下发短期受控凭据。

## 4. 资源规范

### 4.1 资源分类与资源树

资源树采用“分类节点 + 资源节点”两层职责，分类只负责目录，资源负责具体数据引用：

```ts
const terrainCategory: ResourceCategoryDefinition = {
  id: "category-terrain",
  name: "地形数据",
  parentId: "category-basic",
  sortOrder: 10,
  status: "enabled",
}
```

资源分类字段规范：

| 字段          | 必填 | 说明                                           |
| ------------- | ---- | ---------------------------------------------- |
| `id`          | 是   | 分类节点唯一标识                               |
| `name`        | 是   | 展示名称                                       |
| `parentId`    | 否   | 父分类；顶层分类省略                           |
| `sortOrder`   | 是   | 列表排序，整数升序，数值越小越靠前             |
| `status`      | 否   | `enabled` / `disabled`，停用后不在资源树中展示 |
| `description` | 否   | 分类说明                                       |

资源节点使用 `categoryId` 挂到分类下，并同样使用 `sortOrder` 排序。`sortOrder` 只影响资源树和资源列表，不参与地图渲染。

### 4.2 资源来源

资源分为两类：

```ts
type ResourceDefinition =
  | ServiceResourceDefinition // 引用数据服务
  | InlineGeoJsonResourceDefinition // 内联 GeoJSON
```

### 4.3 服务资源

```ts
const demResource: ServiceResourceDefinition = {
  id: "resource-dem-guangxi",
  name: "广西地形",
  remark: "用于默认场景地形加载和地形夸张演示",
  categoryId: "category-terrain",
  sortOrder: 10,
  status: "enabled",
  origin: "service",
  kind: "terrain",
  sourceId: "source-dem-guangxi",
  extent: {
    west: 104.4464,
    south: 20.9019,
    east: 112.0574,
    north: 26.3887,
  },
}
```

`id` 的职责固定：

- `id` 是资源唯一标识，`LayerDefinition.resourceId`、后端外键和 mock 数据内部引用只能使用 `id`。

资源不额外定义业务编码。后续如外部系统确实需要稳定业务编码，必须先补充明确的对接场景和唯一性规则，再通过规范版本评审加入。

`kind` 取值：

```text
imagery / terrain / vector / tileset / model / annotation / analysis
```

影像资源额外用 `usage` 区分：

```ts
const basemapResource: ServiceResourceDefinition = {
  id: "resource-image-basemap",
  name: "遥感底图",
  categoryId: "category-imagery",
  sortOrder: 20,
  origin: "service",
  kind: "imagery",
  sourceId: "source-image-basemap",
  usage: "basemap",
  extent: {
    west: 104.4464,
    south: 20.9019,
    east: 112.0574,
    north: 26.3887,
  },
}
```

服务资源字段规范：

| 字段                      | 必填 | 说明                                              |
| ------------------------- | ---- | ------------------------------------------------- |
| `id`                      | 是   | 资源唯一标识，被 `layer.resourceId` 引用          |
| `name`                    | 是   | 资源名称                                          |
| `origin`                  | 是   | 固定为 `service`                                  |
| `kind`                    | 是   | 资源类型                                          |
| `sourceId`                | 是   | 引用 `DataSourceConfig.id`                        |
| `categoryId`              | 否   | 所属资源分类                                      |
| `sortOrder`               | 是   | 资源树排序，整数升序，数值越小越靠前              |
| `status`                  | 否   | `enabled` / `disabled`，停用后不允许新增引用      |
| `extent`                  | 是   | WGS84 覆盖范围，用于“缩放至资源/图层”             |
| `tags`                    | 否   | 业务标签                                          |
| `createdAt` / `updatedAt` | 否   | 管理端展示与审计时间，9 月可省略，10 月由后端返回 |
| `remark`                  | 否   | 备注，用于管理端展示和运维说明                    |

`extent` 是 WGS84 经纬度包围盒，字段为 `west`、`south`、`east`、`north`；地形、实景三维、点云和模型可补充 `minimumHeight`、`maximumHeight`，单位为米。`extent` 保存资源级覆盖范围，不保存在数据服务接入上，因为同一个 WMS/WFS 服务可能包含多个子图层，各子图层的实际范围可能不同。

注册服务时，系统按协议自动读取范围并预填表单；管理员可以在保存前确认或修改。重新测试服务时，如果原范围是自动读取结果，则允许更新；如果管理员已手工修改，则展示新旧范围并让管理员选择，不静默覆盖。

| 协议                     | 自动读取规则                                             | 人工输入要求                         |
| ------------------------ | -------------------------------------------------------- | ------------------------------------ |
| `tianditu`               | 服务为全域瓦片；9 月前端预填广西业务范围，仅用于定位     | 可按业务专题调整，不裁剪瓦片服务     |
| `terrain-quantized-mesh` | 读取 `layer.json` 的范围字段；没有范围字段时无法自动读取 | 读取失败时必须手工填写               |
| `xyz`                    | XYZ 模板地址没有标准元数据文件                           | 必须手工填写                         |
| `wms`                    | 读取 `GetCapabilities` 中所选 Layer 的地理范围           | 元数据缺失或明显不合理时手工修正     |
| `wmts`                   | 读取 `GetCapabilities` 中所选 Layer 的 BoundingBox       | 元数据缺失或坐标系转换失败时手工填写 |
| `wfs`                    | 读取 `GetCapabilities` 中 FeatureType 的 WGS84 范围      | 元数据缺失或数据明显不完整时手工填写 |
| `geojson`                | 请求 GeoJSON 后计算要素包围盒                            | 文件不可访问时必须手工填写           |
| `3d-tiles`               | 读取 `tileset.json` 根节点 boundingVolume 并换算为 WGS84 | 解析失败时必须手工填写               |
| `gltf`                   | 普通 glTF 只有模型局部坐标，没有可靠地理参考             | 必须手工填写                         |

“缩放至资源/图层”按 ArcGIS 和 QGIS 的 `Zoom To Layer` 语义设计：

- 影像、矢量、GeoJSON：使用数据自身包围盒；源数据不是 WGS84 时，先转换到 WGS84 再保存。
- DEM、3D Tiles、模型：使用水平包围盒，必要时带高度范围，用于计算 Cesium 相机飞行目标。
- 服务资源使用 `resource.extent` 定位；内联 GeoJSON 可在加载后计算要素包围盒。
- `extent` 缺失或无法计算时，按钮置灰并提示缺少定位范围，不做猜测式定位。

### 4.4 内联 GeoJSON 资源

绘制成果、分析结果、用户上传 shp/geojson 后的临时预览，都可以用内联 GeoJSON 表达：

```ts
const bufferResource: InlineGeoJsonResourceDefinition = {
  id: `resource-buffer-${crypto.randomUUID()}`,
  name: "缓冲区分析结果",
  sortOrder: 0,
  origin: "inline-geojson",
  kind: "analysis",
  data: {
    type: "FeatureCollection",
    features: [],
  },
}
```

约束：

- 内联数据适合小型结果和演示数据。
- 用户上传 GeoJSON / JSON 单文件最大 20MB，ZIP Shapefile 最大 50MB；上传解析后只在会话内存中保留。
- 10 月后端可把内联 GeoJSON 转为成果表或对象存储文件。

## 5. 图层规范

`LayerDefinition` 引用 `resourceId`，并携带类型化样式。

### 5.1 图层类型

```ts
type LayerType = "imagery" | "terrain" | "vector" | "tileset" | "model" | "annotation" | "analysis"
```

映射关系：

| LayerType    | 常见来源                  | 说明                                 |
| ------------ | ------------------------- | ------------------------------------ |
| `imagery`    | XYZ/WMS/WMTS/GeoJSON 外框 | 底图或叠加影像                       |
| `terrain`    | quantized-mesh            | 可配置多个；运行态单选，不支持透明度 |
| `vector`     | WFS/GeoJSON               | 道路、水系、行政区等                 |
| `tileset`    | 3D Tiles                  | 倾斜摄影、白膜、点云、BIM            |
| `model`      | glTF/GLB                  | 手工单体模型                         |
| `annotation` | 绘制标注成果              | 张的模块挂载                         |
| `analysis`   | 分析结果                  | 陈的模块挂载                         |

### 5.2 样式能力

| 图层类型                  | 样式字段                         |
| ------------------------- | -------------------------------- |
| `imagery`                 | `opacity`                        |
| `terrain`                 | 无透明度；只允许显隐             |
| `vector`                  | 填充、轮廓、标注、挤出高度、图标 |
| `tileset`                 | `opacity`                        |
| `model`                   | `opacity`                        |
| `annotation` / `analysis` | 复用矢量样式                     |

透明度范围：`0 <= opacity <= 1`。

### 5.3 sortOrder 与 renderOrder 规则

图层配置同时包含两个排序字段，二者语义固定，不做自动转换：

| 字段          | 作用         | 排序规则                         | 使用位置                   |
| ------------- | ------------ | -------------------------------- | -------------------------- |
| `sortOrder`   | 列表/树排序  | 整数升序，数值越小越靠前         | 资源树、图层树、方案列表   |
| `renderOrder` | 地图渲染叠放 | 整数升序写入，数值越大越靠近视点 | 影像、矢量、模型等渲染图层 |

`sortOrder` 参考后台管理系统和资源目录的常见 `sort` / `sort_order` 用法，列表默认按 `ORDER BY sortOrder ASC, id ASC` 展示。资源分类、资源、图层分组、图层和方案都使用这一规则。

`renderOrder` 采用地图和前端常见的 `zIndex` 语义，数值越大显示越靠上、越靠近视点。CSS `z-index`、Google Maps `zIndex`、OpenLayers `zIndex`、Leaflet `zIndex` 以及 Cesium 影像层索引都符合这一习惯；Mapbox Style 虽然用图层数组而非数字，也是数组后面的层显示在上层。

`renderOrder ASC` 指的是引擎写入顺序，不是显示优先级排序。Cesium 影像层集合遵循“后写入者在上方”的规则，因此引擎必须先写入 `renderOrder` 小的底层，再写入 `renderOrder` 大的高层。例如 `1、2、3` 依次写入后，显示结果从下到上也是 `1、2、3`。如果按降序写入，就必须插入到集合指定位置或反转数组，容易引入偏差。

- `sortOrder` 只决定树和列表位置，不参与渲染。
- `renderOrder` 只决定渲染叠放，不决定图层树位置。
- 分组 `groupId` 只决定树的位置，不参与渲染优先级。
- `imagery` 按 `renderOrder` 升序依次写入 Cesium `ImageryLayerCollection`，后写入的层在集合更上方，因此数值越大越靠上；多个底图和影像叠加层允许同时显示。
- `terrain` 不参与渲染叠放。Cesium 当前只有一个 `scene.setTerrain()` 地形槽位，多个地形图层只能作为备选配置单选启用，不能像影像一样叠加。
- 同一父节点下资源 `sortOrder`、同一分组下图层 `sortOrder` 建议不重复；重复时按 `id` 稳定排序。
- 同一方案中图层 `renderOrder` 建议不重复；重复时按 `id` 稳定排序。

### 5.4 DEM 图层示例

```ts
const demLayer: TerrainLayerDefinition = {
  id: "layer-dem-guangxi",
  name: "广西地形",
  type: "terrain",
  resourceId: "resource-dem-guangxi",
  visible: true,

```

## 6. 分组与方案规范

分组使用扁平数组表达树，避免父子字段重复维护：

```ts
const groups: LayerGroupDefinition[] = [
  { id: "group-base", name: "基础数据", sortOrder: 10, defaultExpanded: true },
  {
    id: "group-terrain",
    name: "地形",
    parentId: "group-base",
    sortOrder: 20,
    defaultExpanded: true,
  },
]
```

图层分组字段规范：

| 字段              | 必填 | 说明                       |
| ----------------- | ---- | -------------------------- |
| `id`              | 是   | 分组唯一标识               |
| `name`            | 是   | 展示名称                   |
| `parentId`        | 否   | 父分组；顶层分组省略       |
| `sortOrder`       | 是   | 图层树排序，数值越小越靠前 |
| `defaultExpanded` | 是   | 图层树初始展开状态         |
| `status`          | 否   | `enabled` / `disabled`     |
| `description`     | 否   | 分组说明                   |

图层节点不单独建树表，统一使用 `LayerDefinition.groupId` 挂到分组下。图层节点在树中的位置由 `sortOrder` 决定；地图上的叠放关系由 `renderOrder` 决定。

`defaultExpanded` 只影响方案首次打开时分组节点是否展开：`true` 表示展开，`false` 表示折叠。用户手动展开或折叠属于临时状态，不回写管理员配置。

方案示例：

```ts
const byDataTypeScheme: LayerSchemeDefinition = {
  schemaVersion: 1,
  id: "scheme-by-data-type",
  name: "默认分组",
  sortOrder: 10,
  groups,
  layers: [demLayer],
  status: "published",
  defaultActive: true,
}
```

规则：

- 管理员可保存多个方案，例如“默认分组”“林地调查”“古树名木”。
- 同一时间地图端只启用一个主方案。
- 切换方案时整体替换旧方案图层，不允许多方案混合叠加。
- 影像底图不限制数量。全域底图可用低 `renderOrder` 兜底，局部高精度影像用更高 `renderOrder` 叠加显示。
- 地形图层不限制配置数量，但同一时间只能启用一个；切换地形时按单选处理。
- 如需“全域中精度地形 + 局部高精度地形”连续融合，应在服务端切片阶段做镶嵌后发布成一个 Terrain 服务，或后续专项设计前端裁剪/融合方案，不能依赖 `renderOrder` 叠加。
- 方案中所有 `resourceId` 必须能解析到资源，所有 `sourceId` 必须能解析到服务接入。

多底图示例：

```ts
const tiandituLayer: ImageryLayerDefinition = {
  id: "layer-tianditu-image",
  name: "天地图影像底图",
  type: "imagery",
  resourceId: "resource-tianditu-image",
  visible: true,
  sortOrder: 10,
  renderOrder: 1,
  style: { opacity: 1 },
}

const districtImageLayer: ImageryLayerDefinition = {
  id: "layer-district-high-resolution",
  name: "某政区高精度遥感影像",
  type: "imagery",
  resourceId: "resource-district-high-resolution",
  visible: true,
  sortOrder: 20,
  renderOrder: 2,
  style: { opacity: 1 },
}
```

渲染时天地图作为全域兜底层放在下方，政区高精度影像按自身覆盖范围叠加在上方；未覆盖区域继续显示天地图。

## 7. 地图端用户状态

```ts
interface TransientSceneState {
  activeSchemeId?: string
  visibilityOverrides: Readonly<Record<string, boolean>>
  temporaryLayers: readonly LayerDefinition[]
}
```

已确认的 9 月规则：

- 用户显隐不保存。
- 刷新页面或关闭浏览器后，恢复管理员方案的默认显隐。
- `visibilityOverrides` 可以临时隐藏默认显示图层，也可以临时显示默认隐藏图层。
- 管理员修改方案并“发布并应用”前，不影响当前地图；切换方案会整体替换正式图层并清空正式图层的显隐覆盖。
- 默认 `visible: false` 的图层采用懒加载：方案应用时只创建树节点和 `loaded` 快照，用户第一次打开开关时才请求服务。
- 默认 `visible: true` 的图层在方案应用后立即加载；失败时保留树节点和错误信息，可重试。
- 临时图层允许存在，包括上传 shp/geojson 做空间分析和内置分析工具生成的结果。
- 临时图层不进入正式方案，不写入 localStorage。
- 资源 `status: "disabled"` 时，引用它的图层不请求服务，树节点显示 `error` 和“资源已停用”；停用不自动删除管理员配置。

## 8. 图层注册接口

张的绘制成果和陈的分析结果统一调用 `LayerRegistry`，禁止直接操作 Viewer。

```ts
interface LayerRegistry {
  applyScheme(bundle: LayerSchemeBundle): Promise<readonly LayerSnapshot[]>
  registerLayer(input: RegisterLayerInput): Promise<LayerSnapshot>
  removeLayer(layerId: string): Promise<void>
  updateLayer(layerId: string, patch: LayerDefinitionUpdatePatch): Promise<LayerSnapshot>
  setLayerVisible(layerId: string, visible: boolean): Promise<LayerSnapshot>
  retryLayer(layerId: string): Promise<LayerSnapshot | undefined>
  flyToLayer(layerId: string): Promise<boolean>
  flyToResource(resourceId: string): Promise<boolean>
  getActiveSchemeId(): string | undefined
  getLayerSnapshots(): LayerSnapshot[]
  onLayerSnapshotsChange(listener: (snapshots: readonly LayerSnapshot[]) => void): () => void
}
```

调用规则：

- `applyScheme` 返回已受理的 `loading` 快照；后续加载成功或失败通过 `onLayerSnapshotsChange` 更新。
- `RegisterLayerInput.origin` 省略时按 `scheme` 处理；用户上传、绘制和分析结果必须传 `temporary`。
- 更新样式时，`patch.style` 必须与图层 `type` 匹配，由注册入口统一校验。
- `terrain` 在地图端按单选处理；调用 `setLayerVisible(layerId, true)` 显示一个地形时，注册器必须隐藏同方案内其他地形图层。

### 8.1 状态机

```text
registerLayer / applyScheme
        |
        v
     loading
      /   \
 loaded   error
```

- `loading`：图层配置已受理，资源正在加载。
- `loaded`：渲染成功。
- `error`：加载失败，保留配置和错误信息，可重试或移除。

### 8.2 临时图层接入示例

```ts
const snapshot = await layerRegistry.registerLayer({
  definition: {
    id: `layer-buffer-${crypto.randomUUID()}`,
    name: "道路缓冲区",
    type: "analysis",
    resourceId: bufferResource.id,
    visible: true,
    sortOrder: 1000,
    renderOrder: 1000,
    style: {
      fillColor: "#48e5ff",
      fillOpacity: 0.25,
      strokeColor: "#37a9ff",
      strokeWidth: 2,
    },
  },
  resource: bufferResource,
  origin: "temporary",
})
```

### 8.3 用户上传接入

地图页图层树是普通用户上传入口。上传流程由 `parseUploadedLayerFile(file)` 统一处理：

1. 校验扩展名和大小：GeoJSON / JSON 最大 20MB，ZIP Shapefile 最大 50MB。
2. JSON 直接解析；ZIP 使用 `shpjs` 解析并合并多个 `FeatureCollection`。
3. 校验至少存在一个有效 Feature 和 WGS84 经纬度坐标。
4. 计算要素包围盒并写入 `InlineGeoJsonResourceDefinition.extent`。
5. 创建 `origin: "temporary"` 的 `LayerDefinition`，加入“临时图层”分组并调用 `registerLayer()`。

上传资源必须设置 `status: "enabled"`；删除临时图层时同步移除渲染实例、临时资源和会话显隐记录。

## 9. 管理端流程

### 9.1 资源注册

1. 管理员选择资源分类 `categoryId` 和资源类型：影像底图、地形、矢量、实景三维、模型等。
2. 系统按资源类型给出可选协议。
3. 协议确定后展示该协议专属字段。
4. 管理员确认名称、覆盖范围、备注和资源树排序 `sortOrder`。
5. 管理员执行连通性测试。
6. 测试通过后保存 `DataSourceConfig` 和 `ResourceDefinition`。

资源类型与协议映射：

| 资源类型          | 可选协议                         |
| ----------------- | -------------------------------- |
| 影像底图/影像叠加 | `tianditu`、`xyz`、`wms`、`wmts` |
| 地形              | `terrain-quantized-mesh`         |
| 矢量              | `wfs`、`geojson`                 |
| 实景三维          | `3d-tiles`                       |
| 手工模型          | `gltf`                           |

### 9.2 连通性测试

| 协议                     | 测试方式                                             |
| ------------------------ | ---------------------------------------------------- |
| `tianditu`               | 校验 `mapType`、`tokenEnvVariable` 与本地 Key 配置   |
| `terrain-quantized-mesh` | 请求 `layer.json`，再抽检一个低层级 `.terrain` 瓦片  |
| `xyz`                    | 替换低层级 `{z}/{x}/{y}` 后请求瓦片                  |
| `wms`                    | 发起 `GetCapabilities` 或带 BBOX 的 `GetMap`         |
| `wmts`                   | 发起 `GetCapabilities` 或抽检 Tile                   |
| `wfs`                    | 发起 `GetCapabilities` 或 `GetFeature&maxFeatures=1` |
| `geojson`                | 请求 URL 并校验 `FeatureCollection`                  |
| `3d-tiles`               | 请求 `tileset.json` 并校验 `root`                    |
| `gltf`                   | 请求模型 URL 并校验状态码与内容类型                  |

测试结果统一为：

```ts
interface ServiceTestResult {
  status: "ok" | "failed"
  message: string
  checkedAt: string
  latencyMs?: number
}
```

### 9.3 图层方案配置

管理员可以：

- 新建、复制、重命名、删除方案。
- 自定义分组树。
- 把已注册资源加入分组。
- 为每个图层设置名称、默认显隐、透明度、矢量样式、图层树排序 `sortOrder` 和渲染优先级 `renderOrder`。
- 设置默认方案。
- 保存并发布方案。

普通地图用户只能：

- 切换方案。
- 控制图层显隐。
- 创建临时图层。

## 10. 与现有代码的关系

- 当前 `src/map/types.ts` 的 `TerrainSource` 是引擎层渲染输入，不是管理端服务目录模型。
- 旧 `.env` DEM 启动加载链路已移除；DEM 服务地址保存在 `src/mock/layers.ts` 的 `TerrainQuantizedMeshDataSource.url`。
- Viewer 创建时不再注册默认底图和默认地形；`LayerRegistry` 按已发布方案下发影像、矢量、模型和地形。
- `LayerRegistry` 负责把 `TerrainQuantizedMeshDataSource` 转成 `TerrainSource`，再调用 `mapController.setTerrainSource()`。
- 业务模块不得绕过 `LayerRegistry` 直接操作 Cesium Viewer。

## 12. 校验规则

保存服务接入、资源、图层、方案前必须校验：

- `id` 全局唯一且非空。
- `protocol` 属于支持的协议枚举。
- HTTP/HTTPS URL 格式合法。
- Terrain URL 以 `/` 结尾且不包含 `layer.json`。
- `resource.sourceId` 能找到对应服务接入。
- `resource.categoryId` 如填写，必须能找到未停用的资源分类。
- `layer.resourceId` 能找到对应资源。
- 服务资源 `extent` 必填，且满足 `west < east`、`south < north`、经度 `-180 ~ 180`、纬度 `-90 ~ 90`；如填写高度，必须满足 `minimumHeight <= maximumHeight`。
- `style` 字段与 `type` 匹配。
- `opacity` 在 0 到 1 之间。
- `sortOrder`、`renderOrder` 为非负整数。
- 资源分类和分组不能形成环。
- 列表按 `sortOrder ASC, id ASC` 排序；渲染按 `renderOrder ASC, id ASC` 依次写入引擎，数值越大越靠近视点。
- 底图和影像叠加层数量不限制。
- 地形图层数量不限制，但保存默认方案时应只有一个 `visible: true` 的地形图层；未选中的地形图层保持 `visible: false`，供地图端单选切换。
