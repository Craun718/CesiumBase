## 2. 设计原则

沿用 v1.0 的七条，并对每条补上**可判定性**——不可判定的原则会退化成口号。

| 原则                   | 含义                                                    | 如何判定                                                        |
| ---------------------- | ------------------------------------------------------- | --------------------------------------------------------------- |
| **扁平优先**           | 同层级容器不叠加多重阴影或渐变，差异靠透明度与边框建立  | 同一规则块内出现 2 个以上 `box-shadow` / 渐变即违规             |
| **玻璃拟态聚焦**       | 仅用于浮在地图之上的浮层、面板、Toast；普通控件保持纯色 | `backdrop-filter` 只允许出现在面板级、模态级、Toast 级选择器上  |
| **令牌唯一来源**       | 颜色 / 间距 / 圆角 / 模糊 / 字号全部来自 `global.css`   | `check:tokens` 的 `color-literal` 规则                          |
| **层级语义化**         | 容器层级决定背景、模糊与 z-index 档位                   | `check:tokens` 的 `z-index-literal` 规则；§7 的档位表           |
| **状态可观测**         | 交互元素必须显式声明五态之一                            | §10 的五态表；焦点环不得被局部抹掉（`focus-outline-none` 规则） |
| **无障碍兜底**         | 颜色不可单独承载信息，状态必须配图标、文字或形状        | §9 清单；评审逐条走查                                           |
| **合成对比度优先**     | 对比度按**文字叠在面板、面板叠在地图**的合成结果算      | `check:contrast`，见 §4.5                                       |
| **唯一来源可机器校验** | 契约中可量化的部分必须有对应检查器，不靠人工记忆        | §13；每条违规清单都标注规则号                                   |

**反例**（v1.0 原样保留，仍然有效）：面板阴影 + 内嵌渐变 + 高斯模糊叠加；所有 `<button>` / `<input>` 都加玻璃模糊；在 scoped SCSS 中复制 token 值；任意层级都用同一模糊强度；hover 才出现反馈、移除焦点环；仅靠 `--cyan` 边框表示选中；在同一按钮里混用实心和线型图标。

## 3. 决策记录

记录**为什么这么定**，避免后人反复推翻。

### D1 保留既有视觉身份，只在令牌层精修

**决策**：保留近黑底 `#030913` + 半透明深蓝面板 + 青色强调 + 蓝色次强调 + 琥珀/玫红告警的配色身份，不切换整体色板。

**理由**：这是大屏的品牌识别，且琥珀/玫红已经承载了告警语义。切换色板（例如改为中性灰 + 绿色）会与既有告警语义冲突，并让全站视觉资产作废。

**代价**：暗色大屏上深蓝面板与地图的对比天然偏低，文字对比度必须靠合成计算而非直觉保证（§4.5）。这是本规范把「合成对比度」列为核心原则的原因。

### D2 分期实施：先视觉后交互

**决策**：先做令牌层视觉重构（低风险、当天可验证），组件库迁移另起批次。

**理由**：视觉改动是「值收敛」，回归面小；组件库迁移会触及交互语义与键盘行为，回归面大。两者混在一个批次里，出问题时无法定位是值改错了还是结构改错了。

### D3 采用 Reka UI，且限定迁移范围

**决策**：引入 Reka UI 承载**有交互语义**的组件（Dialog / AlertDialog / Toast / RadioGroup / Collapsible / Tree / Tabs）；下列**不迁移**：

| 不迁移                       | 理由                                                                                                  |
| ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| 原生 `<select>`（17 处）     | 原生控件在暗色大屏上需要深度 `:deep()` 定制，Reka `Select` 会引入浮层定位与虚拟滚动的新问题，收益为负 |
| 原生 `type="range"`（14 处） | 原生 range 的键盘与无障碍语义已完整，且已用 `accent-color` 与令牌对齐                                 |
| 布局容器、面板外壳           | 无交互语义，`FloatingWindow` 已是稳定契约（§8.1）                                                     |
| 纯展示型卡片、表格           | 无交互语义；表格的粘性列、排序属业务逻辑，搬进组件库反而增加耦合                                      |

**理由**：组件库的价值在交互语义与键盘 / 焦点管理，不在「用了某个库」。无交互语义的组件迁移只增加依赖与回归面。

**不引入 jsdom / vitest / `@vue/test-utils`**：仓库测试基线是纯逻辑 `node:test`（§13.3），为了迁移组件库而引入 DOM 测试环境会改变整条测试链路，属独立决策。

## 4. 颜色系统

### 4.1 三层结构

```
@theme  （Tailwind 调色板层）  —— 原子的、无语义的颜色与尺度
  ↓ 引用
:root   （语义角色层）         —— 表面、文本、强调、层级、角色别名
  ↓ 引用
组件 scoped SCSS              —— 只允许引用上述两层，不得出现颜色字面量
```

规则：

- **只有 `global.css` 可以出现颜色字面量。** 其他任何文件出现 `#rgb` / `#rrggbb` / `rgb()` / `rgba()` / `hsl()` 都是违规（`check:tokens` 的 `color-literal` 规则）。
- `color-mix()` 的颜色参数同样必须引用令牌，不得写字面量（`color-mix-literal` 规则）。
- 新增语义令牌进 `:root`，**不进 `@theme`**——它们是语义角色，不是 Tailwind 调色板。只有需要被 Tailwind 工具类直接消费的原子值才进 `@theme`。

### 4.2 强调色族

| 令牌      | 角色        | 使用约束                           |
| --------- | ----------- | ---------------------------------- |
| `--cyan`  | 主强调色    | 焦点环、选中态、主 CTA、激活图标   |
| `--blue`  | 次强调色    | 面板底、hover 底、次级按钮底       |
| `--amber` | 告警        | 仅用于警告语义；**不得用作装饰色** |
| `--rose`  | 错误 / 危险 | 仅用于错误文字、危险操作、删除语义 |

规则：

- 同一视图内 `--amber` 与 `--rose` 不得同时作为装饰出现；它们只在有对应语义时出现。
- 强调色不得同时承载两种语义（例如 `--rose` 不能既表示「错误」又表示「品牌」）。

### 4.3 表面阶梯与「可否压地图」

表面令牌**必须**按下表理解。关键区分是**有效 alpha**：面板叠在 3D 地图之上，alpha 越低，地图透出的亮色越会吃掉文字对比度。

| 令牌                | 有效 alpha  | 可否直接压地图 | 说明                                   |
| ------------------- | ----------- | -------------- | -------------------------------------- |
| `--surface-0`       | 1.00        | ✅             | 背景根色，不透明                       |
| `--surface-1`       | 0.86        | ✅             | **可直接压地图的最低档**，面板默认底色 |
| `--surface-2`       | 0.92        | ✅             | 浮起面板                               |
| `--surface-3`       | 0.94        | ✅             | 输入区                                 |
| `--surface-overlay` | 0.72        | ✅（仅遮罩）   | 模态遮罩，其上必定还有不透明卡片       |
| `--surface-chrome`  | 1.00        | ✅             | 顶栏 / 底栏（`#0a2540`）               |
| `--row-sticky-*`    | 0.96 ~ 0.98 | ✅             | 表格粘性列，见 §4.3.1                  |
| `--glass-bg`        | 0.86        | ✅             | `--surface-1` 的别名                   |
| `--glass-bg-raised` | 0.92        | ✅             | `--surface-2` 的别名                   |
| `--color-panel@N%`  | 0.86 × N%   | ❌             | 见 §4.3.2                              |

#### 4.3.1 `--row-sticky-*` 必须是不透明常量

表格粘性列要盖在「行内容 + 半透明行底 + 半透明面板 + 3D 地图」的**未知合成结果**之上。只有不透明（或接近不透明）常量才能保证内容从其下方滚过时不透视。因此这四个令牌使用字面 `rgba()` 而非 `color-mix()`——这是对现状值的忠实登记，**不是**可以随手替换的魔法值。

#### 4.3.2 `--color-panel` 只能用于「背后已有面板」的嵌套浮层

`--color-panel` 自身的 alpha 是 0.86 × 78% = **0.671**，组件再写 `color-mix(in srgb, var(--color-panel) N%, transparent)` 会再乘一次 N%。叠加后有效 alpha 可能远低于 0.86，压在地图上时对比度不足。

**已知缺口**：`MapCompass` 正是这种写法，且是**两块底衬不同的元素**——`.compass-dial` 用 `--color-panel` 再乘 88%（有效 α 0.757），`.compass-heading` 再乘 78%（有效 α 0.671）。两者压在亮影像上时对比度均不足。

**不要照抄这里的比值**：比值随令牌值变动，以 `pnpm check:contrast` 的实测输出为准，本文件只登记「哪里不达标、为什么、为什么没修」。当前登记在 `KNOWN_GAPS` 的共三项：

1. `裸地图（焦点环）` —— `--ring-color` 是 `--cyan` 的 85%，压在亮底图上过浅。**与底衬透明度无关**，是环色本身的问题。
2. `地图 + --color-panel@88（指北针表盘）`
3. `地图 + --color-panel@78（指北针读数）`

三项均属**已知且未修**，不是达标。

### 4.4 危险令牌的历史教训

`--glass-bg` / `--glass-bg-raised` 曾定义为 `color-mix(in srgb, var(--surface-N) 78%, transparent)`（α 仅 0.671），压地图时 `--text-muted` 只有约 1.77:1。现已收窄为 `--surface-1` / `--surface-2` 的**别名**，语义限定为「仅可用于已有面板之内」。

v1.0 §6 登记的 `--glass-bg` 数值（`rgba(7,20,42,0.62)` 等）与代码实际不符，不要引用。

### 4.5 对比度下限与判定方法

**判定方法**：对比度必须按**合成后结果**计算，不按令牌字面值。

```
C = α · C_layer + (1 − α) · C_backdrop        ← 逐层自外向内套用
```

`color-mix(in srgb, X p%, transparent)` 在预乘 alpha 空间下等价于「保留 X 的色相通道，把 alpha 缩放到 `α_X × p/100`」。`check:contrast` 按该语义实现。

**底图样本**（取全部样本中的最小值作为判定值）：

| 样本     | 值        | 说明                                 |
| -------- | --------- | ------------------------------------ |
| 纯白     | `#ffffff` | 比真实更严格的上界（云、雪、亮影像） |
| 亮影像   | `#8caabe` |                                      |
| 中影像   | `#506478` |                                      |
| 暗影像   | `#0a1a2e` |                                      |
| 大屏底色 | `#030913` |                                      |

> `backdrop-filter: blur()` 会对底图做局部低通，真实底图比纯白样本平缓。因此「只在纯白下不达标」的项目**可以**登记豁免，但仍需在实际底图上人工确认。

**阈值**：

| 类别               | 阈值    | 依据                       |
| ------------------ | ------- | -------------------------- |
| 文本               | ≥ 4.5:1 | WCAG 1.4.3 AA              |
| 非文本（焦点环等） | ≥ 3:1   | WCAG 1.4.11 / 2.4.11       |
| 三档文本相邻比     | ≥ 1.25  | 保证层级等距递减，不靠手感 |

**实测值**（2026-09-15，面板 `--surface-1` 上、最差底图纯白下）：

| 令牌                     | 比值  | 判定 |
| ------------------------ | ----- | ---- |
| `--color-text-primary`   | 11.17 | ✅   |
| `--color-text-secondary` | 7.60  | ✅   |
| `--color-text-muted`     | 4.93  | ✅   |
| `--cyan`                 | 8.20  | ✅   |
| `--blue`                 | 4.81  | ✅   |
| `--amber`                | 7.09  | ✅   |
| `--rose`                 | 4.97  | ✅   |

三档文本阶梯：primary/secondary = **1.47**，secondary/muted = **1.54**（下限 1.25）。

### 4.6 豁免登记

豁免必须写明依据，且必须仍然命中；不再命中的豁免会被检查器报告为「需清理」，**不允许静默存在**。

| 令牌              | 依据                                         |
| ----------------- | -------------------------------------------- |
| `--text-disabled` | WCAG 1.4.3 明确豁免禁用态控件的对比度要求    |
| `--rose-deep`     | 仅用于填充与描边（错误图标底等），不承载文本 |

**豁免 ≠ 已知缺口。** 已知缺口（§4.3.2）是「确实未达标且未修复」，检查器会单独打印并要求决策。

## 6. 间距、圆角、阴影、模糊

数值见 `global.css`。本节只规定**选择规则**。

### 6.1 间距

- 面板内边距必须使用 `--space-panel-compact` / `--space-panel-default` / `--space-panel-elevated` 三档角色令牌，不得直接写 `padding: 12px`。
- 列表项内边距（左右）推荐 `--space-5`(10) 或 `--space-6`(12)，与列表项间距 `--space-stack-sm` 形成 1:1 的内/外比例。
- 组件级布局间距优先用 `--space-stack-*` 复合角色。

### 6.2 圆角

- 6 档：`--radius-xs`(3) / `sm`(4) / `md`(6) / `lg`(8) / `xl`(12) / `pill`(999)。
- **同一组件内部层级最多 2 档圆角**，超过视为过度装饰。
- 圆形头像、状态点用 `border-radius: 50%`，不计入档位。

### 6.3 阴影

- 3 档深度：`--shadow-1`(行内浮起) / `--shadow-2`(面板、浮窗) / `--shadow-3`(模态、主面板)。
- 同层级阴影最多 1 档，禁止叠加深阴影形成「双层阴影」。
- 玻璃面板只在底色透明时叠加阴影；不允许在阴影上再加 `inset` 阴影。
- 自定义发光必须基于 `--ring` 体系，禁止引入强调色族之外的霓虹色。

> **历史缺陷提醒**：`--shadow-1/2/3` 曾因引用了从未定义的 `--abyss`（正确名是 `--color-abyss`）而全站失效。新增令牌时若引用不存在的变量且不给回退值，整条声明会在计算值阶段失效且**不报错**。`check:tokens` 的 `undefined-var` 规则专门拦截这类写法。

### 6.4 模糊

- 仅两档：`--blur-panel`(16px) 用于面板级，`--blur-toast`(10px) 用于 Toast。
- `backdrop-filter` 必须引用令牌，禁止直接 `blur(10px)`。
- 必须同时写 `-webkit-backdrop-filter` 以兼容 Safari。
- 普通按钮、输入框、行内 chip **不使用**玻璃模糊（性能开销 + 视觉杂乱）。

## 7. 层级与 z-index

### 7.1 全局档位

集中定义在 `global.css` 的 `:root`，**唯一来源**：

| 令牌           | 值  | 用途                     |
| -------------- | --- | ------------------------ |
| `--z-base`     | 0   | 地图 / 3D 视口           |
| `--z-content`  | 10  | 地图覆盖物（绘制、测量） |
| `--z-status`   | 20  | 顶栏 / 底栏              |
| `--z-rail`     | 30  | 左右操作栏               |
| `--z-floating` | 40  | 浮窗面板、二级菜单       |
| `--z-modal`    | 50  | 模态弹窗、确认对话框     |
| `--z-toast`    | 60  | Toast、瞬时反馈          |
| `--z-tooltip`  | 70  | Tooltip、Popover         |

### 7.2 规则

- **浮层一律使用 `var(--z-*)`，不得写 ≥ 10 的裸数字**（`z-index-literal` 规则）。
- **Toast 浮在模态之上**（60 > 50）是有意为之：Toast 是操作结果反馈，被模态遮住会让用户看不到错误。这是相对收敛前的行为变更，已确认。
- 新增层级档位必须先写入 `global.css`，再在 §7.1 登记。

### 7.3 例外：组件内局部层叠

组件内部的 `z-index: 0~9`（例如面板内标题对装饰层的层级、表格粘性列对行内容的层级）**保持原样**，不映射到全局档位——它们表达的是组件内部结构关系，映射到全局档位反而会改变语义。

## 8. 组件 API 契约

### 8.1 `FloatingWindow`

面板外壳的**唯一**实现。同类功能不得另建弹窗、抽屉或卡片容器。

| Prop       | 类型                            | 说明                              |
| ---------- | ------------------------------- | --------------------------------- |
| `id`       | `string`                        | 与菜单入口的 `aria-controls` 对应 |
| `title`    | `string`                        | 同时作为 `aria-label`             |
| `tag`      | `string?`                       | 右上角短标签                      |
| `variant`  | `"panel" \| "submenu"`          | 面板 / 二级菜单                   |
| `align`    | `"left" \| "right" \| "center"` | 进入动画方向                      |
| `closable` | `boolean`                       | 默认 `true`                       |

| Emit    | 说明                            |
| ------- | ------------------------------- |
| `close` | 点击关闭按钮或按下 `Esc` 时触发 |

视觉契约：圆角 `--radius-panel`、背景 `--panel-bg`、边框 `--panel-border`、模糊 `--blur-panel`、阴影 `--panel-shadow`、内边距 `--window-padding`（可用 `--window-*` 局部变量覆盖）、`overflow: hidden`。

### 8.2 Props 约定

- `disabled` / `loading` / `error` 必须与 `aria-*` 对应暴露（`aria-disabled` / `aria-busy` / `aria-invalid`）。
- 标题用 `title` prop；描述用 `description`；避免用 `label` 当标题。
- 关闭回调统一 `onClose`；异步结果统一 `onComplete` / `onError`。

### 8.3 状态与层级分离

- **二级菜单**仅放 `command`（点击即执行并反馈）与 `trigger`（切换状态或模式）两类入口。
- 需要输入、选择、编辑、确认或其他后续操作的功能，一律进**三级功能面板**。
- 二级菜单与三级面板**使用独立状态源**：打开/切换三级只更新对应面板状态；关闭三级只清空该状态，**不得在关闭事件里推断或恢复二级**；关闭二级时同步关闭该入口对应的三级面板。

### 8.4 类命名

- 状态前缀 `is-` / `has-`：`is-active`、`is-dragging`、`has-error`。
- 变体前缀用组件名：`btn-primary`、`panel-elevated`。
- 角色类用 `text-*`：`text-body`、`text-label`。

## 9. 无障碍基线

对照 ARIA APG 与 WCAG 2.2 AA。

### 9.1 必做

| 项           | 要求                                                                   |
| ------------ | ---------------------------------------------------------------------- |
| 面板语义     | `role="region"` + 中文 `aria-label`（`FloatingWindow` 已实现）         |
| 菜单         | `aria-expanded` + `aria-controls` 关联到面板 `id`                      |
| 互斥选择     | `role="radiogroup"` 容器 + `role="radio"` + `aria-checked`             |
| 开关         | `role="switch"` + `aria-checked`（**不是** `aria-pressed`）            |
| 图标按钮     | 必须提供 `title` 与可访问名称（`aria-label`）                          |
| 焦点可见     | 任何可聚焦元素在 `:focus-visible` 下必须有可见焦点环                   |
| 焦点不可遮挡 | 固定 UI / 浮层不得遮住键盘焦点所在的控件（WCAG 2.2 AA）                |
| 退出路径     | 面板与模态必须支持 `Esc` 关闭；模态必须提供「取消」                    |
| 危险操作     | 必须二次确认；确认弹窗不得点击遮罩关闭                                 |
| 禁用原因     | 禁用项必须说明原因，不能只是变灰                                       |
| 减少动效     | `prefers-reduced-motion: reduce` 下压到 0.001ms（`global.css` 已实现） |

### 9.2 焦点环

**统一由 `global.css` 的 `:focus-visible` 规则提供，组件不得在局部抹掉。**

`outline: none` 只允许在下列两种情况出现：

1. 同一规则块内给出了替代焦点环（`outline` 或 `outline-offset`）——此时 `check:tokens` 视为已替代，不报错。
2. 元素紧贴 `overflow: hidden` / `overflow: auto` 容器边缘，外扩环会被裁切——此时改用**内嵌环** `outline-offset: var(--ring-inset)`。

### 9.3 状态不得仅靠颜色

选中、错误、警告、禁用等状态必须至少有两种可感知通道（颜色 + 图标 / 文字 / 形状 / 边框）。色盲用户与高对比模式用户依赖这一点。

## 10. 交互五态

所有交互元素（按钮、开关、列表项、卡片、菜单项）必须显式声明五态：

| 状态     | 视觉                                                   | 可交互 | 可聚焦 |
| -------- | ------------------------------------------------------ | ------ | ------ |
| default  | 基础样式                                               | 是     | 是     |
| hover    | 边框 / 背景透明度 +10%，`cursor: pointer`              | 是     | 是     |
| pressed  | `transform: scale(0.97)` + `opacity: 0.85`（全局已有） | 是     | 是     |
| focus    | `outline: var(--ring)` + `outline-offset`              | 是     | 是     |
| disabled | `opacity` 降低 + `cursor: not-allowed` + 禁用原因提示  | 否     | 否     |

**反馈时机**：

- 即时反馈（< 100ms）：按钮 pressed、开关切换。
- 完成反馈（< 300ms）：列表插入、Toast 出现。
- 异步反馈（> 300ms）：必须显示 spinner 或骨架屏，不允许空白等待；按钮置 `aria-busy="true"` 且 `disabled`。

**反馈位置**：操作反馈优先显示在**所属功能面板内**，不得用全局浮层打断地图操作。

## 11. 图标与文案

### 11.1 图标

- **仅使用 Bootstrap Icons**（`<i class="bi bi-*">`）。自定义图形用 inline SVG 并以 `currentColor` 继承文字色。
- 5 档尺寸：`--icon-xs`(12) / `sm`(14) / `md`(16) / `lg`(20) / `xl`(24)。
- 实心 vs 线型：工具栏与菜单入口用线型；选中/激活态用实心；状态点与徽章用实心；表单内交互图标用线型。
- **同一按钮内 hover 前后必须保持同风格**，只切换颜色与透明度。
- 图标不可独立承载状态含义，必须配合文字、徽章或边框。
- **禁止 emoji 充当结构化图标。**

### 11.2 文案

- 界面文案使用中文；短标签、状态、模式可用大写英文。
- 标题、按钮、列表文本必须在窄面板内**换行或截断**，不得溢出、遮盖相邻控件。
- 需要截断时用省略号并保证指针与键盘用户都能取到完整文本。
- 危险操作的按钮文字使用动词短语（「删除图层」），不用「确定」。

### 11.3 控件选型

| 语义     | 控件                                       |
| -------- | ------------------------------------------ |
| 立即动作 | 按钮                                       |
| 二元状态 | 开关（`role="switch"`）                    |
| 数值范围 | 滑杆 + 配数字输入                          |
| 互斥选项 | 单选组（`role="radiogroup"`）              |
| 文本输入 | 表单字段（必须带可见标签，不能只有占位符） |

## 13. 检查与准入

### 13.1 可执行门禁

```bash
pnpm check:tokens     # 设计令牌静态检查（第 1~5 条规则）
pnpm check:contrast   # 合成对比度检查（第 6~8 条规则）
```

两者的退出码为 0 才算通过。`check:contrast` 在存在**已知缺口**时仍返回 0，但会打印缺口清单——缺口是「已知且未修」，不是达标。

### 13.2 完整验证链

```bash
pnpm format:check && pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

`pnpm build` 写 `dist/`、`pnpm test` 写 `dist-test/`，均已被 `.gitignore` 忽略。

### 13.3 测试基线

单元测试使用 Node 内置 `node:test`：`pnpm test` 先经 `tsc -p tsconfig.test.json` 编译到 `dist-test`，再运行 `node --test`。

> **陷阱**：`tsconfig.test.json` 的 `include` 是**显式白名单**，不是 glob。新增纯函数模块若不同步加入，`pnpm test` 会静默不编译、测试假绿。新增测试文件时必须一并检查该文件。

**组件目前零测试覆盖。** 因此回归策略是把逻辑挡在组件之外：

1. 界面改动提交**不得修改 `tests/**`**。若某测试必须改，视为「业务逻辑泄漏进组件」的信号，须拆独立提交并写明原因。
2. 任何要移入组件的判断 / 派生逻辑，先在 `*.ts` 里实现并补测试（顺序：纯函数 + 测试 → 组件引用）。
3. 组件只允许 import 已测模块。
4. 每期提交后 `pnpm test` 必须绿且**用例数不减**。

### 13.4 人工验证（LLM 无法替代）

静态检查覆盖不到的部分必须人工执行：

1. **DOM 计算值审计**：遍历含可见文本的元素取 `getComputedStyle().color`，向上累积祖先背景色的 alpha 得到有效背面，遇 `<canvas>` 用固定样本色（`#ffffff` 与 `#0a1a2e` 各跑一次），输出对比度 < 4.5 的清单。
2. **截图对比**：1920×1080 / 1440×900 / 1024×768 × 关键屏。评审规则是「**色相不变、层级不降、无新增魔法值**」，不是像素一致。
3. **键盘走查**：Tab 序完整、每个可聚焦元素有可见焦点环、`Esc` 可关闭面板、面板内滚动不带动地图。

> 开发服务器只能由人工启动。LLM 不得运行、重启或接管 `pnpm dev` / `pnpm preview`；运行时问题只能基于用户提供的 URL、日志、控制台输出或网络请求信息排查。

## 附录 C 术语表

| 术语                    | 含义                                                                                   |
| ----------------------- | -------------------------------------------------------------------------------------- |
| **令牌**                | `global.css` 中定义的自定义属性，是数值的唯一来源                                      |
| **有效 alpha**          | 多层半透明叠加后，某一层在最终合成结果中的实际不透明度                                 |
| **合成对比度**          | 按「文字叠在面板、面板叠在地图」逐层合成后再算出的 WCAG 对比度，不是令牌字面值的对比度 |
| **表面阶梯**            | `--surface-0…3` 等背景令牌构成的层级体系                                               |
| **压地图**              | 元素直接叠在 3D 地图之上（背后没有其他面板衬底）；此时底衬 alpha 必须足够高            |
| **五态**                | default / hover / pressed / focus / disabled                                           |
| **豁免**                | 准则本身不适用（如禁用态、纯填充色），登记后检查器不再报错                             |
| **已知缺口**            | 确实未达标且未修复，检查器每次打印但不阻断；**不等于达标**                             |
| **二级菜单 / 三级面板** | 导航层级：一级侧栏 → 二级菜单（`command` / `trigger`）→ 三级功能面板                   |
