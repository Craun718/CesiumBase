# 资源与图层管理设计规范 v1.0

> 状态：v1.0 设计稿

> 适用范围：服务接入、资源目录、图层管理、地图方案切换与管理端诊断
> 本规范取代此前的 v0.1/v0.2 设计文档；旧版设计文档已从仓库移除。

## 1. 目标

本规范把当前容易混在一起的“服务、资源分类、资源、图层和方案”重新定义为一条清晰的上游链路：

```text
服务接入：数据从哪里来
    ↓ sourceId
资源目录：实际取哪份数据
    ↓ resourceId
图层管理：在场景中如何组织和显示
```

设计目标：

- 服务接入真正承担上游连接、测试和元数据发现职责。
- 一个服务接入可以派生多个资源，不再要求每新增一个图层就重复新增服务。
- 管理员尽可能少地手工填写名称、类型、范围、坐标系和缩放级别。
- 统一接入向导可以一次完成服务连接、数据发现、资源登记和加入方案。
- 图层方案保持简单，不引入发布版本、发布快照、回滚和历史配置。
- 图层加载失败时，普通用户只收到明确但安全的提示，管理员按目标对象进行诊断。

## 2. 范围

### 2.1 v1.0 实现范围

- 数据模型升级为 `1.0`，不兼容 v0.2 旧字段。
- 服务接入、资源目录和图层管理的字段职责重构。
- 协议注册表、Profile、标准元数据文件和 `dataset.json` 兜底规则。
- 服务与资源统一接入向导。
- 资源批量发现、选择和创建。
- 图层方案启用、停用、默认和保存规则。
- 地图方案选择、图层失败提示和管理员针对性诊断。
- 首批协议完整验收：3D Tiles、DEM、天地图、GDAL XYZ。

### 2.2 协议实现边界

协议注册表和通用向导应覆盖当前全部协议，但首批完整验收只包含：

- `3d-tiles`：GridMaster `box + transform`、OSGBLab `sphere + external tileset`
- `terrain-quantized-mesh`：`layer.json` + `meta.json`
- `tianditu`：影像和注记
- `xyz`：GDAL `gdal raster tile` 输出的 XYZ 瓦片和 `stacta.json`

WMS、WMTS、WFS、GeoJSON、glTF 保留协议定义和字段结构，后续按相同 Profile 流程逐步补齐。

### 2.3 非目标

- 不保存服务接入、资源或图层方案的历史版本。
- 不实现发布快照、版本回滚和批量重发。
- 不自动遍历完整瓦片目录、完整 3D Tiles 内容树或全部 tileset 子文件。
- 不把大规模影像的全部像素读入内存或浏览器。
- 不在当前开发阶段实现账户、角色和真实权限控制。

## 3. 核心术语

| 术语               | 含义                                               |
| ------------------ | -------------------------------------------------- |
| 服务接入           | 一个可测试、可发现的数据连接或服务入口             |
| 资源分类           | 资源目录树的目录节点                               |
| 资源               | 从服务中选择并登记的具体数据，或内联的业务成果     |
| 协议绑定 `binding` | 资源在服务中选择的具体数据项及其协议参数           |
| 图层               | 某个方案中引用资源的显示实例                       |
| 图层方案           | 一组已保存的分组、图层、显隐、顺序和样式配置       |
| Profile            | 同一协议下由不同版本、工具或结构差异形成的格式档案 |
| 标准元数据         | 协议或工具自带的入口元数据文件                     |
| `dataset.json`     | 可选的统一元数据补充和人工覆盖清单                 |
| 验证指纹           | 用于判断验证结果是否失效的配置与元数据摘要         |

### 3.1 Profile 的含义

Profile 不是 GDAL 的 `--profile` 切片方案。本文中的 Profile 专指协议格式档案，例如：

- `gridmaster-box-transform`
- `osgblab-sphere-ecef`
- `gdal-raster-tile-stacta`

Profile 由系统根据结构自动识别，不能作为普通业务字段要求管理员手工选择。识别结果写入验证诊断，允许在自动识别失败时人工固定。

## 4. 三层职责

### 4.1 服务接入

服务接入负责：

- 连接协议和协议版本。
- 数据根地址或服务基础地址。
- 认证信息和连接级参数。
- 启用状态。
- 连接测试。
- 元数据入口探测和候选数据发现。
- 协议 Profile 自动识别。
- 服务级验证状态和指纹。

服务接入不负责：

- 保存具体 WMS Layer、WMTS Layer、WFS TypeName 等数据选择。
- 保存资源名称、分类和业务标签。
- 保存图层样式、显隐和渲染顺序。

### 4.2 资源目录

资源目录负责：

- `sourceId` 和稳定的 `bindingKey`。
- 协议 `binding`。
- 资源类型 `kind`。
- 名称、分类、标签和备注。
- 覆盖范围及范围来源、质量。
- 启用状态。
- 资源级验证状态和指纹。
- 资源在目录树中的排序。

资源目录不负责：

- 保存连接地址和认证信息。
- 保存图层别名、显隐、渲染排序和样式。
- 持有图层方案。

### 4.3 图层管理

图层管理负责：

- 方案名称、描述和排序。
- 方案启用状态和默认标记。
- 方案内分组。
- 引用哪些资源。
- 图层别名、默认显隐、树排序和渲染排序。
- 图层类型对应的显示样式。

图层管理不负责：

- 保存服务连接配置。
- 保存资源 binding、范围或验证结果。
- 复制资源和服务的完整配置。

## 5. 字段职责矩阵

| 字段或职责                                | 服务接入       | 资源目录       | 图层管理       |
| ----------------------------------------- | -------------- | -------------- | -------------- |
| 协议、根地址、认证、连接参数              | 拥有           | 只读           | 不保存         |
| 服务启用状态                              | 拥有           | 只读           | 不保存         |
| 连接测试、发现入口、Profile 识别          | 拥有           | 只读           | 不保存         |
| `sourceId`                                | 不保存         | 拥有           | 不保存         |
| `bindingKey`、协议 `binding`              | 不保存         | 拥有           | 不保存         |
| 资源类型 `kind`                           | 推导           | 保存系统生成值 | 推导图层类型   |
| 资源名称、分类、标签、备注                | 不保存         | 拥有           | 只用于默认名称 |
| `extent`、`extentSource`、`extentQuality` | 仅返回发现结果 | 拥有           | 只读           |
| 服务验证结果                              | 拥有           | 只读           | 只读           |
| 资源验证结果                              | 不保存         | 拥有           | 只读           |
| 方案、分组、图层别名                      | 不保存         | 不保存         | 拥有           |
| 显隐、树排序、渲染排序、样式              | 不保存         | 不保存         | 拥有           |
| 方案启用状态、默认标记                    | 不保存         | 不保存         | 拥有           |

核心原则：

> 服务接入决定“怎么连”，资源决定“取哪份数据”，图层决定“在场景里怎么显示”。

## 6. 数据模型 v1.0

### 6.1 版本

目录模型版本固定为 `1.0`：

```ts
export const CATALOG_DATA_MODEL_VERSION = "1.0" as const
```

v1.0 不提供 v0.2 字段兼容读取。类型、fixture、适配器、加载器和测试应一次性迁移，禁止同时保留两套字段作为正常运行路径。

### 6.2 实体 ID 与 binding key

不同类型使用不同身份的字段：

| 字段          | 责任             | 生成方                |
| ------------- | ---------------- | --------------------- |
| `source.id`   | 服务接入实体身份 | 后端；开发阶段为 UUID |
| `resource.id` | 资源实体身份     | 后端；开发阶段为 UUID |
| `layer.id`    | 方案内图层身份   | 后端；开发阶段为 UUID |
| `bindingKey`  | 上游数据项身份   | 协议适配器规范化生成  |

唯一性规则：

- `(sourceId, bindingKey)` 在正式资源中唯一。
- `bindingKey` 不包含资源名称，不受资源改名影响。
- 后端对外 ID 使用不可变字符串，不暴露数据库数值主键。
- 当前阶段不保留 `revision` 或版本历史；多人并发保存按最后写入覆盖处理。

单数据协议的 `bindingKey` 固定为 `root`。多数据协议使用规范化 key，例如：

```text
wms:<layer>
wmts:<layer>#<tileMatrixSet>#<style>
wfs:<typeName>
```

如果上游 key 发生变化，系统将旧资源标记为“上游已不存在”，新项标记为“未登记”，由管理员显式重新映射，不能自动改绑资源。

`bindingKey` 和 `binding` 是内部识别与运行时绑定字段，管理端不直接展示协议 JSON。后端接入后可以返回上游数据项 ID，但仍需映射为稳定 key 以保证幂等发现；管理端只展示可读的“上游数据项”摘要。

### 6.3 目录快照

```ts
export interface CatalogSnapshot {
  readonly modelVersion: "1.0"
  readonly sources: readonly ServiceSourceDefinition[]
  readonly resourceCategories: readonly ResourceCategoryDefinition[]
  readonly resources: readonly ResourceDefinition[]
  readonly layerSchemes: readonly LayerSchemeDefinition[]
}
```

正式目录不保存临时上传、绘制和分析结果。临时资源、临时图层、当前用户选择的方案和当前会话错误记录属于运行状态。

### 6.4 服务接入

```ts
interface ServiceSourceBase {
  readonly id: string
  readonly name: string
  readonly description?: string
  readonly sortOrder: number
  readonly enabled: boolean
  readonly verification: VerificationState
  readonly createdAt?: string
  readonly updatedAt?: string
}

export type ServiceSourceDefinition =
  | (ServiceSourceBase & { readonly protocol: "tianditu"; readonly connection: TiandituConnection })
  | (ServiceSourceBase & {
      readonly protocol: "terrain-quantized-mesh"
      readonly connection: TerrainConnection
    })
  | (ServiceSourceBase & { readonly protocol: "xyz"; readonly connection: XyzConnection })
  | (ServiceSourceBase & { readonly protocol: "wms"; readonly connection: WmsConnection })
  | (ServiceSourceBase & { readonly protocol: "wmts"; readonly connection: WmtsConnection })
  | (ServiceSourceBase & { readonly protocol: "wfs"; readonly connection: WfsConnection })
  | (ServiceSourceBase & { readonly protocol: "geojson"; readonly connection: GeoJsonConnection })
  | (ServiceSourceBase & {
      readonly protocol: "3d-tiles"
      readonly connection: ThreeDTilesConnection
    })
  | (ServiceSourceBase & { readonly protocol: "gltf"; readonly connection: GltfConnection })
```

连接对象只保存连接级信息：

```ts
export interface ThreeDTilesConnection {
  /** 3D Tiles 服务根目录；入口文件固定为 tileset.json。 */
  readonly rootUrl: string
}

export interface TerrainConnection {
  readonly rootUrl: string
  readonly requestVertexNormals?: boolean
  readonly requestWaterMask?: boolean
}

export interface XyzConnection {
  /** 数据根地址；有 stacta.json 时优先读取并派生瓦片模板。 */
  readonly rootUrl: string
  /** 无标准元数据时允许人工填写。 */
  readonly urlTemplate?: string
  readonly subdomains?: readonly string[]
  readonly minimumLevel?: number
  readonly maximumLevel?: number
  readonly tilingScheme?: "web-mercator" | "geographic"
}

export interface WmsConnection {
  readonly baseUrl: string
  readonly version?: "1.1.1" | "1.3.0"
  readonly authToken?: string
}

export interface WmtsConnection {
  readonly baseUrl: string
  readonly version?: "1.0.0"
  readonly authToken?: string
}

export interface WfsConnection {
  readonly baseUrl: string
  readonly version?: "1.1.0" | "2.0.0"
  readonly authToken?: string
}
```

`protocol` 在服务被资源引用后不可修改。根地址、认证和连接参数允许修改，但必须提示影响范围并重新验证。

### 6.5 资源分类与资源

```ts
export interface ResourceCategoryDefinition {
  readonly id: string
  readonly name: string
  readonly parentId?: string
  readonly description?: string
  readonly sortOrder: number
  readonly status?: "enabled" | "disabled"
}

interface ResourceDefinitionBase {
  readonly id: string
  readonly name: string
  readonly categoryId?: string
  readonly sortOrder: number
  readonly enabled: boolean
  readonly remark?: string
  readonly tags?: readonly string[]
  readonly createdAt?: string
  readonly updatedAt?: string
}

export interface ServiceResourceDefinition extends ResourceDefinitionBase {
  readonly origin: "service"
  readonly sourceId: string
  readonly bindingKey: string
  readonly binding: ResourceBinding
  readonly kind: ResourceKind
  readonly extent?: GeoExtent
  readonly extentSource?: ExtentSource
  readonly extentQuality?: ExtentQuality
  readonly verification: VerificationState
}
```

规则：

- `kind` 由 `binding.protocol` 唯一推导，界面不提供手工选择。
- `binding.protocol` 必须与来源服务协议一致，由系统生成。
- 影像的显示顺序由图层 `renderOrder` 决定，资源层不保存“底图/叠加层”类型。
- `extent` 允许缺省。能否启用包含该资源的方案由协议验证规则决定。
- 找不到资源分类时归入系统“未分类”，不自动创建任意分类。

### 6.7 图层、分组和方案

```ts
export interface LayerSchemeDefinition {
  readonly id: string
  readonly name: string
  readonly description?: string
  readonly sortOrder: number
  readonly status: "enabled" | "disabled"
  readonly defaultActive: boolean
  readonly groups: readonly LayerGroupDefinition[]
  readonly layers: readonly LayerDefinition[]
  readonly createdAt?: string
  readonly updatedAt?: string
}
```

方案规则：

- 不再存在 `draft`、`published`、发布快照和版本历史。
- `status` 表示地图用户是否可以选择该方案。
- 全系统最多一个 `defaultActive`，且必须是启用方案。
- `defaultActive` 只影响地图首次打开或没有会话选择时的方案。
- 启用的方案不允许删除，必须先停用。
- 停用方案可以编辑和保存，重新启用后继续使用当前配置。
- 图层和分组属于具体方案；同一资源可以形成多个图层并加入多个方案。

### 6.8 验证状态

```ts
export interface VerificationIssue {
  readonly level: "info" | "warning" | "error"
  readonly code: string
  readonly message: string
  readonly path?: string
}

export interface VerificationState {
  readonly status: "unverified" | "verified" | "failed" | "stale"
  readonly checkedAt?: string
  readonly fingerprint?: string
  readonly profile?: string
  readonly message?: string
  readonly issues: readonly VerificationIssue[]
}
```

服务验证和服务资源验证分别保存：

- 服务验证检查根地址、认证、协议入口和发现能力。
- 资源验证检查具体 binding、元数据、范围、最小数据读取和运行时映射。
- 关键配置或元数据指纹变化后，验证状态变为 `stale`。
- `warning` 不阻止保存；存在 `error` 时不能启用引用该资源的方案。

### 6.9 删除规则

- 服务被资源引用时禁止删除。
- 资源被任一方案图层引用时禁止删除。
- 方案删除只删除方案、分组和图层，不删除资源和服务。
- 删除前必须展示引用列表。
- 开发阶段允许通过“从方案中移除引用后再删除”的显式操作批量解除引用，不执行隐式级联删除。

## 7. 协议注册表、Profile 与元数据发现

### 7.1 协议配置结构

协议实现集中在 `src/features/data/protocols/`，建议结构：

```text
protocols/
  registry.ts
  protocolTypes.ts
  protocols.json
  shared/
    http.ts
    fingerprint.ts
    extent.ts
  3d-tiles/
    adapter.ts
    profiles.ts
  terrain-quantized-mesh/
    adapter.ts
  tianditu/
    adapter.ts
  xyz/
    adapter.ts
    profiles.ts
```

协议配置负责声明：

- 协议标识、显示名称和资源类型。
- 根地址字段和连接参数。
- 入口元数据候选文件及读取顺序。
- Profile 检测规则。
- 标准元数据字段映射。
- 必需字段和校验规则。
- 是否支持子图层发现。
- 资源 binding 字段。

代码适配器负责：

- HTTP 请求、认证和超时。
- XML Capabilities 解析。
- `box + transform`、ECEF `sphere` 等坐标计算。
- 范围、坐标系和缩放级别规范化。
- 少量瓦片或内容文件抽样。
- 指纹计算和验证结果生成。

### 7.2 统一发现结果

所有协议适配器返回同一数据结构：

```ts
export interface MetadataFileStatus {
  readonly path: string
  readonly role: "standard" | "supplement" | "vendor" | "override"
  readonly status: "read" | "missing" | "invalid" | "skipped"
  readonly fingerprint?: string
}

export interface DiscoveryResult {
  readonly sourceId: string
  readonly protocol: DataSourceProtocol
  readonly profile?: string
  readonly status: "complete" | "partial" | "failed"
  readonly metadataFiles: readonly MetadataFileStatus[]
  readonly items: readonly DiscoveryItem[]
  readonly issues: readonly VerificationIssue[]
}

export interface DiscoveryItem {
  readonly key: string
  readonly parentKey?: string
  readonly name: string
  readonly kind: ResourceKind
  readonly selectable: boolean
  readonly binding?: ResourceBinding
  readonly extent?: GeoExtent
  readonly extentSource?: ExtentSource
  readonly extentQuality?: ExtentQuality
  readonly levelRange?: { readonly min: number; readonly max: number }
  readonly tile?: TileMetadata
  readonly profile?: string
  readonly diagnostics?: Readonly<Record<string, unknown>>
}
```

规则：

- `items` 使用平面数组，层级通过 `parentKey` 表达。
- 协议适配器必须返回稳定的 `key`，用于 `(sourceId, key)` 去重。
- 普通发现只读取根级入口元数据。
- 允许有限抽样验证内容可用性，禁止完整目录扫描。
- 错误使用 `info / warning / error` 分级。

### 7.3 Profile 检测

Profile 检测优先级：

1. `dataset.json.profileHint`。
2. 协议标准结构特征。
3. 通用协议解析。

结构检测示例：

- `asset.version`
- `root.boundingVolume` 是 `region`、`box` 还是 `sphere`
- 根节点是否存在 `transform`
- `extensionsUsed / extensionsRequired`
- 是否存在 external tileset
- 是否存在 implicit tiling

生成器名称只能作为辅助信息，不能单独决定 Profile。自动检测失败时：

- 使用通用规范解析。
- 标记为 `partial`。
- 记录 `warnings`。
- 允许管理员固定兼容 Profile，但固定值必须通过结构校验。

Profile 定义和测试由代码维护，不允许管理员在运行期创建任意解析规则。

### 7.4 元数据优先级

元数据来源优先级固定为：

```text
dataset.json 显式覆盖
  > 协议标准元数据
  > 工具补充元数据
  > 推导结果
  > 人工确认
```

规则：

- `dataset.json` 与人工确认值必须带指纹或确认时间。
- 标准元数据和补充元数据冲突时不得静默覆盖。
- 所有冲突写入 `issues` 并在资源详情中显示来源。
- 指纹变化后旧验证状态失效。

### 7.5 dataset.json

`dataset.json` 是可选的标准元数据补充和人工覆盖清单，不替代 `tileset.json`、`layer.json` 或 `stacta.json`。

建议结构：

```ts
export interface DatasetMetadataFile {
  readonly schemaVersion: 1
  readonly name?: string
  readonly kind?: ResourceKind
  readonly entry?: string
  readonly crs?: string
  readonly extent?: GeoExtent & { readonly quality?: ExtentQuality }
  readonly levelRange?: { readonly min: number; readonly max: number }
  readonly profileHint?: string
  readonly sourceFiles?: readonly string[]
  readonly fingerprint?: string
  readonly params?: Readonly<Record<string, unknown>>
}
```

规则：

- 它只描述当前数据集，不保存服务根地址和认证。
- 所有字段可选，只保存标准文件无法提供或被人工修正的信息。
- `entry` 是相对于数据根目录的路径。
- 找不到适合协议的位置时，文件放在数据根目录。
- `params` 只用于无法进入公共字段的协议扩展。
- 标准元数据完整时不要求创建该文件。

### 7.6 指纹

指纹只覆盖小型配置和元数据，不遍历瓦片：

```ts
export interface MetadataFingerprint {
  readonly etag?: string
  readonly lastModified?: string
  readonly contentHash?: string
  readonly normalizedConfigHash?: string
}
```

规则：

- HTTP 优先使用 `ETag` 和 `Last-Modified`。
- 不可用时对根级小型元数据文件计算 SHA-256。
- 指纹只用于变更检测，不作为安全签名。
- 指纹变化后验证状态变为 `stale`。

### 7.7 首批协议的元数据来源

| 协议               | 标准文件                          | 补充文件                    | 选择粒度                            |
| ------------------ | --------------------------------- | --------------------------- | ----------------------------------- |
| 3D Tiles           | `tileset.json`                    | `dataset.json`              | 一个数据集一个资源                  |
| Quantized Mesh DEM | `layer.json`                      | `meta.json`、`dataset.json` | 一个数据集一个资源                  |
| 天地图             | 无远程文件                        | 协议参数                    | 一个地图类型一个资源                |
| GDAL XYZ           | `stacta.json`                     | `dataset.json`              | 一个瓦片数据集一个资源              |
| WMS                | `GetCapabilities`                 | `dataset.json`              | 一个子图层一个资源                  |
| WMTS               | `GetCapabilities`                 | `dataset.json`              | 一个 Layer + TileMatrixSet 一个资源 |
| WFS                | `GetCapabilities` 或 `GetFeature` | `dataset.json`              | 一个 TypeName 一个资源              |

### 7.8 3D Tiles Profile

首批支持两个 Profile。

#### `gridmaster-box-transform`

识别特征：

- `asset.generatetool` 包含 `GridMaster`。
- 根节点存在 `boundingVolume.box`。
- 根节点存在 `transform`。

适配器行为：

- 将根 `box` 的八个角通过 `root.transform` 转换到 ECEF。
- 将 ECEF 角点转换为 WGS84。
- 得到水平范围和高程范围。
- 范围质量标记为 `derived`。
- 不遍历全部 1931 个节点，只读取根级范围；验证时可抽样一个内容文件。

#### `osgblab-sphere-ecef`

识别特征：

- `asset.generatetool` 包含 `OSGBLab` 作为辅助。
- 根节点不存在 `transform`。
- 根节点使用 `boundingVolume.sphere`。

适配器行为：

- 将 sphere 中心和半径解释为 ECEF 包围球。
- 按球面纬度包络计算局部 WGS84 范围，避免将局部数据扩为全球纬度。
- 范围质量标记为 `conservative`。
- 支持内容指向外部 tileset，但发现阶段不为计算总范围遍历全部子树。

通用 3D Tiles 适配器还必须读取：

- `asset.version`
- `gltfUpAxis`
- `extensionsUsed / extensionsRequired`
- 根 `geometricError` 和 `refine`

### 7.9 DEM

入口文件为 `layer.json`，可选补充 `meta.json`。

字段优先级：

1. `dataset.json.extent`
2. `layer.json.valid_bounds`
3. `meta.json.latLonBounds`
4. `meta.json.bounds`
5. `layer.json.bounds`

若 `layer.json.bounds` 表示全球范围而 `valid_bounds` 表示业务范围，以 `valid_bounds` 为准。两个真实范围来源不一致时产生 warning，不静默选择。

可自动读取：

- `format`
- `projection`
- `scheme`
- `minzoom / maxzoom`
- `tiles`
- `extensions`

### 7.10 天地图

天地图没有可扫描的数据元数据文件，使用协议配置：

- `mapType: imagery | vector`
- 本地 Key 环境变量
- 子域
- 最小和最大级别

资源类型固定为 `imagery`。是否作为底图由图层方案中的层级和 `renderOrder` 决定。默认范围使用项目业务参数，允许管理员覆盖，不进行远程元数据扫描。

### 7.11 GDAL XYZ

首选切片命令：

```powershell
gdal raster tile --config GDAL_CACHEMAX 1024 --config GDAL_DISABLE_READDIR_ON_OPEN=YES --tiling-scheme WebMercatorQuad --convention xyz --min-zoom 1 --max-zoom 20 -r bilinear --webviewer stac D:/data/cun_yx_3857.tif D:/data/xhtlyx
```

已有瓦片补元数据命令：

```powershell
gdal raster tile --config GDAL_CACHEMAX 1024 --config GDAL_DISABLE_READDIR_ON_OPEN=YES --tiling-scheme WebMercatorQuad --convention xyz --min-zoom 1 --max-zoom 20 -r bilinear --resume --webviewer stac D:/data/cun_yx_3857.tif D:/data/xhtlyx
```

`gdal raster tile --webviewer stac` 会生成 `stacta.json`，其中包含：

- `bbox` 和 `geometry`
- `tiles:tile_matrix_sets`
- 各级 `tileMatrix`
- `tiles:tile_matrix_links`
- `asset_templates.bands.href`
- `proj:code`
- `proj:transform`

资源默认类型为 `imagery`。是否作为底图由图层方案中的层级和 `renderOrder` 决定。

GDAL `--profile` 不是本文 Profile。它只表示切片方案，例如 `mercator`、`geodetic`、`raster`。

不要通过 GDAL 或浏览器读取完整影像。需要读取源影像范围时使用：

## 8. 管理流程

### 8.1 统一接入向导

服务、资源和图层三个页面复用同一个接入向导：

```text
1. 选择协议
2. 填写连接参数并测试/发现
3. 选择上游数据项
4. 确认批量资源元数据
5. 选择保存结果
```

第一步必须先选择协议。资源类型由协议自动推导，不再先选资源类型反推协议。

第二步读取根级元数据并执行有限验证。发现失败时允许继续手工登记，但资源验证默认是 `unverified` 或 `failed`。

第三步根据协议返回平面列表或树：

- WMS 等有层级协议用 `parentKey` 显示树。
- 单数据协议只有一个 `root` 项。
- 已登记项显示“已存在”。
- 新项可以选择。
- 上游已不存在项不能选择。

第四步在所有写入发生前统一确认：

- 统一分类、启用状态和命名规则。
- 支持逐行修改名称、范围和启停状态。
- warning/error 必须明确提示。
- 已存在项只能刷新元数据，不能重复创建资源。

第五步提供：

- 仅保存服务接入
- 保存服务接入和资源
- 保存并加入当前图层方案

### 8.2 服务接入页面

页面职责：

- 维护服务连接的增删改查。
- 按协议分组展示服务列表。
- 执行连接测试和重新发现。
- 查看关联资源。
- 显示服务级验证状态和影响范围。

服务列表默认按具体协议折叠分组，组顺序固定。搜索和状态筛选跨组执行，搜索结果仍保留所属协议组。可以切换为扁平列表；`sortOrder` 表示协议组内排序。

服务协议被资源引用后不可修改。根地址、认证和连接参数可以修改，但保存前必须展示影响资源；保存后相关验证失效。

### 8.3 资源目录页面

资源目录使用三栏结构：

```text
左侧：资源分类树
中间：资源列表
右侧：资源详情
```

“新增资源”提供：

- 选择已有服务接入
- 接入新服务

选择已有服务时直接进入发现步骤。资源类型只读，由协议推导；只有发现失败或缺少标准元数据时才开放协议 binding 和范围的人工兜底编辑。

资源列表应显示：

- 名称
- 类型
- 来源服务
- 分类
- 启用状态
- 验证状态
- 范围是否可用
- 被多少个方案和图层引用

资源删除仍受图层引用保护。

### 8.4 图层管理页面

图层管理使用三栏结构：

```text
左侧：方案列表
中间：方案内分组和图层
右侧：图层编辑
```

方案操作：

| 状态 | 操作                               |
| ---- | ---------------------------------- |
| 启用 | 保存方案信息、停用、复制、设为默认 |
| 停用 | 保存方案信息、启用、复制、删除     |

方案操作规则：

- 创建方案后直接生成停用方案，不弹“是否启用”。
- 新建方案预置“基础底图”分组，并在天地图影像资源存在时自动加入该资源。
- 复制方案生成新的停用方案，复制全部分组和图层，使用新 ID，不继承默认标记。
- 启用方案只让地图用户可以切换，不自动改变其他用户当前地图。
- 停用方案可以完整编辑、保存和配置。
- 启用方案不允许删除，必须先停用。
- 全部方案都不能删除最后一个启用方案；停用最后一个启用方案时，地图清空正式图层并显示通用提示。

### 8.5 方案保存规则

保存分为三个责任：

1. 方案信息保存：名称、描述、默认标记和方案排序。
2. 图层保存：名称、备注、显隐、分组、树排序、渲染排序和样式。
3. 结构操作：添加/删除图层、分组和排序，确认后立即保存。

地图更新规则：

- 保存当前用户正在查看的启用方案：立即更新当前地图。
- 保存非当前方案：只更新配置，不切换当前地图。
- 保存停用方案：只更新配置，不在地图方案列表出现。
- 服务或资源修改后：不自动刷新现有地图；下一次图层加载、方案保存或页面刷新时使用新配置。

### 8.6 资源加入方案

“添加图层”入口提供：

- 选择已有资源
- 接入新数据

选择已有资源时，允许一次选择多个资源并：

- 选择目标分组
- 设置默认显隐
- 设置排序起点
- 设置渲染顺序起点
- 应用类型默认样式

同一资源可以重复加入同一方案或多个方案，因为每个图层拥有独立的显示配置。

### 8.7 方案启用校验

启用方案前校验：

- 所有资源引用存在且资源已启用。
- 所有服务引用存在且服务已启用。
- 服务验证和资源验证无 `error`。
- 有 warning 时允许启用，但必须确认。

存在停用资源、失效引用或验证 error 时禁止启用。停用方案仍允许保存不完整配置。

## 9. 地图端行为

### 9.1 方案列表

- 地图用户只能看到启用方案。
- 方案按 `sortOrder` 排序。
- 地图首次打开或没有会话选择时使用管理员设置的默认方案。
- 当前标签页使用 `sessionStorage` 记住用户主动选择的方案。
- 关闭标签页后，新会话恢复默认方案。
- 用户主动切换方案时不修改默认方案。

### 9.2 当前方案被停用

若管理员停用了用户正在查看的方案：

- 用户端自动切换默认方案。
- 显示自动消失提示“当前方案已停用，请联系管理员”。
- 不展示停用原因、内部验证详情或服务地址。

### 9.3 图层加载失败

普通用户只看到自动消失的提示。提示必须列出失败图层名称；如果失败图层较多，仍按用户要求列出全部名称。

提示不显示：

- 服务地址
- 协议参数
- 上游资源名称
- 错误堆栈
- 重试或数据管理入口

普通用户不访问数据管理页面。开发阶段暂不实现权限控制；后端接入后必须保护 `/data` 页面、管理 API 和运行诊断接口。

### 9.4 不执行完整扫描

发现、验证和诊断遵循以下边界：

- 3D Tiles 只读根元数据，可选抽样一个内容文件。
- DEM 只读 `layer.json`，可选读取 `meta.json`。
- GDAL XYZ 只读 `stacta.json`，可选抽样瓦片。
- WMS/WMTS/WFS 只读 Capabilities 或单条测试请求。
- 打开数据总览和诊断页面时不自动扫描全部服务。
- 管理员点击某个失败图层后，只检查该图层对应的资源和服务链。

## 10. 管理员诊断

数据总览提供“运行诊断”区块，只展示当前应用会话中已知的图层失败快照。不会主动向所有上游服务发送请求。

每个失败项显示：

```text
图层
  -> 资源
    -> 服务接入
      -> 最近验证状态
      -> 失败原因
```

管理员可以：

- 查看服务接入详情
- 查看资源 binding 和范围
- 重新测试该服务
- 重新验证该资源
- 定位到对应方案和图层

诊断只针对所选图层链执行，禁止批量扫描全部上游。

## 11. 验证与指纹

服务验证流程：

1. 校验连接配置。
2. 请求协议入口或 Capabilities。
3. 识别 Profile。
4. 执行最小连通性测试。
5. 生成 fingerprint。

资源验证流程：

1. 校验 binding 和来源协议一致。
2. 读取具体数据元数据。
3. 规范化和校验范围。
4. 抽样最小瓦片或内容。
5. 生成 fingerprint。

发布/启用规则：

- 只有没有 `error` 的方案能启用。
- 验证状态为 `stale` 时，必须重新验证才能继续启用方案。
- `warning` 需要管理员确认，但不阻止启用。

## 12. 状态、选择与临时数据

### 12.1 正式状态

- 服务：`enabled / disabled`
- 资源：`enabled / disabled`
- 方案：`enabled / disabled`
- 图层：`visible`

### 12.2 会话状态

以下数据只保留在 Pinia 或 sessionStorage，不进入正式目录：

- 当前标签页选中的地图方案
- 图层显隐覆盖
- 临时上传、绘制和分析图层
- 当前会话已知的图层失败快照
- 未保存的编辑状态

### 12.3 默认方案

- 系统最多一个默认方案。
- 默认方案必须是启用方案。
- 默认方案停用前必须先设置另一个启用方案为默认。
- 设置默认只影响地图首次打开，不立即切换当前地图。

## 18. 关键验收标准

1. 一个服务接入可以稳定派生多个资源。
2. 新增资源不再要求先手工创建重复服务。
3. WMS/WMTS/WFS 子图层标识只存在于资源 binding。
4. 3D Tiles、DEM 和 GDAL XYZ 能自动读取首批元数据。
5. `dataset.json` 只在标准元数据不足时作为兜底。
6. 资源发现可重复执行且不会生成重复资源。
7. 图层方案不再存在草稿、发布快照、版本号和历史回滚。
8. 启用方案只有通过验证后才能被地图用户选择。
9. 地图用户只看到简洁失败提示，管理员只诊断目标图层链。
10. 所有发现和诊断流程都不执行完整目录扫描。
